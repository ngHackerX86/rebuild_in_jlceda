# 使用指南

主流程：把 KiCad PCB 转成嘉立创EDA 专业版中的可编辑工程。已有 Gerber 的独立检查与打包见 [Gerber 工具](../kicad_jlc_exporter/README.md)。

## 开始前

- 已验证环境：Windows 10/11、KiCad 10.0.8、嘉立创EDA 专业版 4.1.100。
- 转换需要 KiCad 自带的 Python（含 `pcbnew`）；命令行示例使用 Python 3.10+。
- 完整流程需要 EDA 已登录且存在在线桌面会话，会在当前账号中新建工程。
- 请保存源 PCB 和 EDA 当前正在编辑的内容。输出需要人工复核，支持范围见 [能力边界](支持范围与限制.md)。

## 安装

### 方法一：发布包

1. 从 [Releases](https://github.com/ngHackerX86/rebuild_in_jlceda/releases) 下载插件包，例如 `rebuild_in_jlc-0.4.0.zip`。若尚未提供该附件，使用下面的源码安装方法。
2. 解压到固定目录，进入含 `install.ps1`、`tools/` 和两个插件文件夹的那一层：

   ```text
   rebuild_in_jlc-0.4.0/
     install.ps1
     tools/
     rebuild_in_jlc/
     kicad_jlc_exporter/
     docs/
   ```

3. 在这个目录打开 PowerShell，执行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
   ```

4. 在 KiCad PCB 编辑器选择 **工具 → 外部插件 → 刷新插件**；必要时重启 PCB 编辑器。

插件需要保留解压目录中的脚本和模板，移动目录后请同步更新 `repo_root`。GitHub 自动生成的 `Source code (zip)` 没有生成好的安装脚本，按源码方法安装即可。

### 方法二：源码手工安装

1. 克隆仓库或下载源码，保存在固定目录。
2. 在 KiCad PCB 编辑器中选择 **工具 → 外部插件 → 打开插件目录**。
3. 将源码中的 `rebuild_in_jlc/` 直接复制到该目录。需要独立 Gerber 工具时，也复制 `kicad_jlc_exporter/`。
4. 刷新插件，在首次配置中把 `repo_root` 指向源码根目录。

源码目录负责提供 `tools/` 和模板，插件目录负责被 KiCad 加载：

```text
源码根目录/                        KiCad 实际插件目录/
  tools/                            rebuild_in_jlc/
  rebuild_in_jlc/                    kicad_jlc_exporter/  （可选）
  kicad_jlc_exporter/
```

## 首次配置

点击 **重建到嘉立创EDA（KiCad→JLCEDA）**；配置缺失时会弹出设置框。若未弹出而需要修改，也可编辑 `%APPDATA%\rebuild_in_jlc\config.json`。

| 字段 | 填什么 |
|---|---|
| 仓库根目录 / `repo_root` | 发布包解压根目录或源码根目录；该目录中能找到 `tools/kicad2eprj3.py` |
| EDA 可执行文件 / `eda_exe` | 实际安装的 `lceda-pro.exe` |
| KiCad Python / `kicad_python` | KiCad 安装目录下的 `bin/python.exe`，带 `pcbnew` |
| 模板 / `template` | 默认使用包内 `rebuild_in_jlc/templates/PCB1_min.epcb2`；手工选择时指向这个文件 |
| 规则档位 / `rules_profile` | 默认 `kicad-min`；它是间距预设，不是源板完整规则的迁移 |

环境变量优先于配置文件。常用覆盖项：`REBUILD_IN_JLC_ROOT`、`JLC_EDA_EXE`、`KICAD_PYTHON`。

CLI 用户可在源码根或发布包解压根目录检查配置；把板文件路径替换为自己的文件：

```powershell
python -m rebuild_in_jlc.pipeline --board "C:\Boards\example.kicad_pcb" --check-config
```

这条命令不向 EDA 账号导入工程。

## 重建可编辑工程

1. 在 KiCad 打开并**保存** PCB。
2. 打开 EDA、登录并确认账号，保存当前编辑内容。
3. 在 KiCad 选择 **工具 → 外部插件 → 重建到嘉立创EDA（KiCad→JLCEDA）**。
4. 等待转换、打包、导入、打开工程、文字补写、规则设置、覆铜、DRC、导出和对照。
5. 若弹出人工覆铜确认，在 EDA 执行 **设计 → 重建覆铜**，再回到**同一个运行窗口**继续。不要通过重新运行整条 CLI 命令来接续它。
6. 在结果窗口打开工作目录，查看 DRC 明细、对照报告和产物。

若 DRC 未通过，按提示决定是否导出诊断资料；导出不代表问题已解决。自动重铺与状态记录的已知限制见 [支持范围与限制](支持范围与限制.md)。

### 输出在哪里

GUI 默认写入 PCB 所在目录下的 `out/rebuild_in_jlc_<时间戳>/`：

| 文件/目录 | 用途 |
|---|---|
| `build/` | 生成的可编辑工程 |
| `rebuild.epro2` | 导入 EDA 用的工程文件 |
| `gerber/Gerber.zip` | 成功执行导出时得到的制造格式文件 |
| `layer_compare.md`、`layer_compare.json` | 对照结果 |
| `run.json`、`step_*.log`、`env.log` | 状态和排错记录；GUI 状态记录仍有已知限制 |

### 结果怎么判断

- **步骤完成**：只表示该步取得返回或产物。
- **DRC 通过**：只针对本次版本、规则和状态。
- **compared**：已取得当前工具支持范围内的统计比较结果，不能推出几何等价。
- **differs / missing_evidence / parse_error**：需要进一步检查差异、补证据或处理解析问题。

最终仍需核对层、孔、开窗、铜几何和网络连通性。完整样例记录见 [验证记录](验证记录.md)。

## 命令行调试

在**源码根目录或完整发布包解压根目录**打开 PowerShell。以下示例的输入路径需要替换：

```powershell
# 只做本地转换，不导入账号
python -m rebuild_in_jlc.pipeline --board "C:\Boards\example.kicad_pcb" --name Example --out "out\Example" --stop-after convert

# 完整流程：会向当前 EDA 账号导入新工程
python -m rebuild_in_jlc.pipeline --board "C:\Boards\example.kicad_pcb" --name Example --out "out\Example"
```

CLI 当前没有 `--resume`，再次执行会从头开始。自动覆铜失败时，优先使用 GUI 同次运行的人工确认；不要用重跑加 `--repour-confirmed` 衔接上次停止点。

更多参数和开发测试见 [开发与测试](开发与测试.md)。`--dry-run` 当前不能当作只读保证；`--export-anyway`、`--continue-on-error` 等诊断选项不会让输出自动变成可制造结论。

## 常见问题

| 情况 | 先检查 |
|---|---|
| 菜单中找不到插件 | 通过 KiCad“打开插件目录”确认实际位置；插件文件夹中应直接有 `__init__.py`，然后刷新或重启 |
| 安装脚本选择的目录不对 | 从 KiCad 复制实际插件目录，再按下面的命令指定 |
| 找不到 tools 或仓库根目录不对 | `repo_root` 是否指向保留的源码/解压根目录 |
| 找不到 pcbnew 或解释器报错 | `kicad_python` 是否为 KiCad 的 `bin/python.exe` |
| 没有 EDA 会话 | EDA 是否已启动、登录并打开过工程 |
| DRC 不通过或报告缺证据 | 先看对应日志和报告；不要只以“流程完成”判断输出 |

指定安装位置时，在含 `install.ps1` 的目录执行下面命令，将占位内容替换为 KiCad 显示的实际路径：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -PluginsDir "<KiCad实际插件目录>"
```

反馈时附版本、失败步骤、脱敏日志和可公开的最小板。日志中可能有本机路径、工程名及账号标识，分享前先检查。
